# Spam Blocker

Spam Blocker 会在社区接受帖子、回复和投票之前，评估它们的垃圾内容风险。社区安装挑战包，由它把每条发布内容发送到一个 Spam Blocker 服务。Bitsocial 在 `spamblocker.bitsocial.net` 运行着一个这样的服务。

- **`@bitsocial/spam-blocker-challenge`** 是社区安装的开源挑战包。它的集成契约、共享 schema 和 API 都是公开的。
- **托管服务**负责为发布内容评分，并提供 CAPTCHA 页面和登录页面。正如[源代码政策](https://github.com/bitsocialnet/spam-blocker/blob/master/docs/architecture/hosted-service-source-policy.md)所解释的，它的详细权重和启发式规则不公开。

**源代码：** [github.com/bitsocialnet/spam-blocker](https://github.com/bitsocialnet/spam-blocker)

## 发布内容如何被检查

1. 社区的挑战把已签名的发布内容发送给服务，服务返回一个介于 0 和 1 之间的风险分数。
2. 低于社区的自动通过阈值时，发布内容通过。等于或高于自动拒绝阈值时，发布内容被拒绝，作者会看到原因。
3. 介于两者之间时，如果作者过去 30 天内的登录已经足够，就会复用这次登录。否则作者会看到一个验证页面：仅靠 CAPTCHA 就能通过时显示 CAPTCHA，否则要求登录。
4. 随后社区向服务核实结果，并针对国家、IP 风险和连接类型应用自己的规则。

上传附件之前，客户端可以先以预检的形式运行同样的检查，这样会被拒绝的作者就根本不会上传。

## 风险分数

| 信号       | 说明                                                                           |
| ---------- | ------------------------------------------------------------------------------ |
| 账户年龄   | 越新的账户，风险分数越高。                                                     |
| Karma      | 在社区中积累的 karma 会降低风险。                                              |
| 作者声誉   | 来自后台索引器的数据，它跟踪哪些作者在各个社区中被接受、被移除或被封禁。       |
| 内容与链接 | 文本和链接分析，包括重复内容。                                                 |
| 发布速率   | 同一作者短时间内连续发帖会提高风险。                                           |
| IP 情报    | 连接类型（Tor、VPN、代理、数据中心）和 IP 风险。原始 IP 地址绝不会提供给社区。 |
| 关联账户   | 从同一网络发帖的账户越多，风险就会逐步升高。                                   |
| 社交验证   | 作者账户此前的登录记录会降低风险。                                             |

## 验证

每完成一步，风险分数都会乘以相应的系数；结果低于 0.4 时，发布内容即通过。

| 步骤                                | 系数     |
| ----------------------------------- | -------- |
| CAPTCHA（Cloudflare Turnstile）     | × 0.7    |
| 使用 Google、Apple 或 Telegram 登录 | × 0.6    |
| 使用另一个不同的提供方登录          | 再 × 0.5 |

如果 CAPTCHA 不够，接下来需要登录。如果登录不够，而 CAPTCHA 能完成检查，接下来就是 CAPTCHA，否则是使用第二个提供方登录。

### 记住的登录

服务会记住作者上次登录所用的账户。之后需要验证的帖子会复用这个账户，就像作者重新登录了一样，前提是作者至少每 30 天用它发一次帖。如果这样已经足够，帖子无需 CAPTCHA 即可通过。社区中与该账户关联的封禁会终止这一机制，从服务中移除该账户的提供方也会终止它。

## 连接策略

社区可以限制来自 Tor、VPN（包括 iCloud Private Relay）、代理和数据中心连接的发布内容。在托管服务上：

- **VPN、代理和数据中心连接**在登录后即可发帖。页面会说明为什么需要登录，以及如何通过关闭 VPN 在不登录的情况下发帖。此后，社区中的封禁也会作用于登录所用的账户。
- **成熟账户**，即曾在 3 个不同的日子里从不受限制的连接通过检查的账户，可以豁免。
- **Tor** 仍然受限，但拥有社区所配置豁免的作者除外：版主角色、社区白名单，或经过验证的 `.bso` 名称。

上传到 Forge Images 的附件遵循同样的规则。通过 VPN、代理或数据中心连接上传时，需要一次借助登录通过的预检，或者一个成熟账户。通过 Tor 上传时，需要经过验证的豁免。

## 隐私

- **运营方**会存储原始 IP 地址和发布内容用于滥用检测，并将 IP 地址发送给第三方提供商进行分类（默认是 proxycheck.io）。
- **社区**只会收到国家代码、IP 风险、连接类型估计以及通过或未通过的结果。它们绝不会收到原始 IP 或登录账户。
- **登录**不会请求任何个人资料数据。服务只会从 Google、Apple 或 Telegram 收到一个账户 ID，绝不会收到姓名、电子邮件或照片。服务会把该 ID 与帖子一起保存，不会自动删除，因此封禁也会作用于该账户。
- **使用 VPN 的作者**在登录时仍能隐藏真实 IP 地址：服务只能看到 VPN 的地址。

## 速率限制

在评分之前，服务会拒绝超出发帖、回复和投票的每小时或每日额度的作者。额度会随账户年龄和良好声誉而增加，并在遭到封禁或移除后减少。

## API

主要路由，相对于 `spamblocker.bitsocial.net/api/v1`：

| 路由                     | 调用方            | 用途                       |
| ------------------------ | ----------------- | -------------------------- |
| `POST /evaluate`         | 挑战 iframe、社区 | 为发布内容评分并创建其会话 |
| `POST /challenge/verify` | 社区              | 读取会话结果和 IP 情报     |
| `POST /precheck`         | 预检 iframe       | 在上传前为草稿评分         |
| `GET /iframe/:sessionId` | 作者的浏览器      | 验证页面                   |
| `POST /upload/authorize` | 作者的客户端      | 为 Forge Images 授权附件   |

完整的契约，包括请求签名和响应 schema，见 [spam-blocker README](https://github.com/bitsocialnet/spam-blocker#api-contract)。
