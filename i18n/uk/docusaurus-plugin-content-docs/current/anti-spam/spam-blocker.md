# Spam Blocker

Spam Blocker оцінює ризик спаму в дописах, відповідях і голосах до того, як спільнота їх прийме. Спільнота встановлює пакет виклику, який надсилає кожну публікацію до сервісу Spam Blocker. Bitsocial підтримує такий сервіс на `spamblocker.bitsocial.net`.

- **`@bitsocial/spam-blocker-challenge`** — це пакет виклику з відкритим кодом, який встановлюють спільноти. Його контракт інтеграції, спільні схеми та API публічні.
- **Розміщений сервіс** оцінює публікації та обслуговує сторінки CAPTCHA і входу. Його детальні ваги й евристики закриті, як пояснює [політика щодо вихідного коду](https://github.com/bitsocialnet/spam-blocker/blob/master/docs/architecture/hosted-service-source-policy.md).

**Вихідний код:** [github.com/bitsocialnet/spam-blocker](https://github.com/bitsocialnet/spam-blocker)

## Як перевіряється публікація

1. Виклик спільноти надсилає підписану публікацію до сервісу, який повертає оцінку ризику від 0 до 1.
2. Якщо оцінка нижча за поріг автоматичного прийняття, заданий спільнотою, публікація проходить. Якщо вона дорівнює порогу автоматичного відхилення або перевищує його, публікація не проходить, і автор бачить чому.
3. Якщо оцінка між цими порогами, повторно використовується вхід автора за останні 30 днів, коли його достатньо. Інакше автор отримує сторінку перевірки: CAPTCHA, якщо самої CAPTCHA може вистачити, або вхід.
4. Потім спільнота звіряє результат із сервісом і застосовує власні правила щодо країни, ризику IP і типу підключення.

Перед завантаженням прикріпленого файлу клієнт може запустити ту саму перевірку як попередню, тож автори, яких було б відхилено, узагалі нічого не завантажують.

## Оцінка ризику

| Сигнал              | Опис                                                                                                         |
| ------------------- | ------------------------------------------------------------------------------------------------------------ |
| Вік акаунта         | Новіші акаунти отримують вищу оцінку ризику.                                                                 |
| Карма               | Накопичена карма у спільноті знижує ризик.                                                                   |
| Репутація автора    | Дані фонового індексатора, який відстежує, яких авторів приймають, видаляють або банять у різних спільнотах. |
| Вміст і посилання   | Аналіз тексту й посилань, зокрема повторюваного вмісту.                                                      |
| Темп публікацій     | Часті послідовні дописи від одного автора підвищують ризик.                                                  |
| Дані про IP         | Тип підключення (Tor, VPN, проксі, дата-центр) і ризик IP. Самі IP-адреси ніколи не передаються спільнотам.  |
| Пов’язані акаунти   | Багато акаунтів, що публікують з однієї мережі, поступово підвищують ризик.                                  |
| Соціальна перевірка | Попередні входи, прив’язані до акаунта автора, знижують ризик.                                               |

## Перевірка

Кожен пройдений крок множить оцінку ризику на коефіцієнт, і публікація проходить, коли результат нижчий за 0.4.

| Крок                                  | Множник  |
| ------------------------------------- | -------- |
| CAPTCHA (Cloudflare Turnstile)        | × 0.7    |
| Вхід через Google, Apple або Telegram | × 0.6    |
| Вхід через другого, іншого провайдера | ще × 0.5 |

Якщо CAPTCHA недостатньо, далі потрібен вхід. Якщо недостатньо входу, далі йде CAPTCHA, коли вона завершує перевірку, а інакше — вхід через другого провайдера.

### Запам’ятовані входи

Сервіс запам’ятовує акаунт, через який автор востаннє входив. Наступний допис, що потребує перевірки, повторно використовує його так, ніби автор увійшов знову, доки автор продовжує публікувати через цей акаунт щонайменше раз на 30 днів. Якщо цього достатньо, допис проходить без CAPTCHA. Це припиняється, якщо в спільноті з’являється бан, пов’язаний з акаунтом, а також якщо провайдера цього акаунта прибрано із сервісу.

## Політики щодо підключень

Спільноти можуть обмежувати публікації з підключень через Tor, VPN (зокрема iCloud Private Relay), проксі та дата-центри. На розміщеному сервісі:

- **Підключення через VPN, проксі та дата-центри** можуть публікувати після входу. Сторінка пояснює, навіщо потрібен вхід і як публікувати без нього, вимкнувши VPN. Бан у спільноті тоді також поширюється на акаунт, через який виконано вхід.
- **Усталені акаунти**, які пройшли перевірку в 3 різні дні з необмежених підключень, звільнені від обмежень.
- **Tor** залишається обмеженим, окрім авторів із винятком, який налаштувала спільнота: роль модератора, білий список спільноти або підтверджене ім’я `.bso`.

Прикріплені файли, які завантажуються до Forge Images, підпадають під ті самі правила. Через VPN, проксі або дата-центр для завантаження потрібна попередня перевірка, пройдена із входом, або усталений акаунт. Через Tor потрібен підтверджений виняток.

## Приватність

- **Оператор** зберігає самі IP-адреси та вміст публікацій для виявлення зловживань і надсилає IP-адреси сторонньому постачальнику для класифікації (типово proxycheck.io).
- **Спільноти** отримують лише код країни, ризик IP, імовірний тип підключення та результат «пройдено» чи «не пройдено». Вони ніколи не отримують саму IP-адресу чи акаунт, через який виконано вхід.
- **Вхід** не запитує жодних даних профілю. Сервіс отримує від Google, Apple або Telegram лише ідентифікатор акаунта, але ніколи ім’я, електронну пошту чи фото. Він зберігає ідентифікатор разом із дописом без автоматичного видалення, тож бан поширюється й на акаунт.
- **Автори, які користуються VPN**, під час входу приховують свою справжню IP-адресу: сервіс бачить лише адресу VPN.

## Обмеження частоти

Ще до оцінювання сервіс відхиляє авторів, які перевищили свою погодинну чи добову квоту на дописи, відповіді та голоси. Квоти зростають із віком акаунта й доброю репутацією та зменшуються після банів чи видалень.

## API

Основні маршрути відносно `spamblocker.bitsocial.net/api/v1`:

| Маршрут                  | Хто викликає                 | Призначення                                     |
| ------------------------ | ---------------------------- | ----------------------------------------------- |
| `POST /evaluate`         | Iframe виклику, спільнота    | Оцінити публікацію та створити для неї сесію    |
| `POST /challenge/verify` | Спільнота                    | Прочитати результат сесії та дані про IP        |
| `POST /precheck`         | Iframe попередньої перевірки | Оцінити чернетку перед завантаженням            |
| `GET /iframe/:sessionId` | Браузер автора               | Сторінка перевірки                              |
| `POST /upload/authorize` | Клієнт автора                | Авторизувати прикріплений файл для Forge Images |

Повний контракт, зокрема підписування запитів і схеми відповідей, наведено в [README spam-blocker](https://github.com/bitsocialnet/spam-blocker#api-contract).
