# Spam Blocker

Spam Blocker は、コミュニティが受け入れる前に、投稿・返信・投票のスパムリスクをスコアリングします。コミュニティはチャレンジパッケージをインストールし、このパッケージが各パブリケーションを Spam Blocker サービスに送信します。Bitsocial は `spamblocker.bitsocial.net` でこのサービスを 1 つ運営しています。

- **`@bitsocial/spam-blocker-challenge`** は、コミュニティがインストールするオープンソースのチャレンジパッケージです。統合コントラクト、共有スキーマ、API は公開されています。
- **ホスト型サービス** はパブリケーションをスコアリングし、CAPTCHA とサインインのページを提供します。[ソースポリシー](https://github.com/bitsocialnet/spam-blocker/blob/master/docs/architecture/hosted-service-source-policy.md) で説明しているとおり、詳細な重み付けとヒューリスティックは非公開です。

**ソースコード:** [github.com/bitsocialnet/spam-blocker](https://github.com/bitsocialnet/spam-blocker)

## パブリケーションのチェックの流れ

1. コミュニティのチャレンジが署名済みのパブリケーションをサービスに送信し、サービスは 0 から 1 までのリスクスコアを返します。
2. コミュニティの自動承認しきい値を下回る場合、パブリケーションは通過します。自動拒否しきい値以上の場合は不合格となり、作成者にはその理由が表示されます。
3. その中間では、作成者の記憶されたサインインで足りる場合、それが再利用されます。足りない場合、作成者には検証ページが表示されます。CAPTCHA だけで通過できる場合は CAPTCHA、そうでなければサインインです。コミュニティが制限している VPN、プロキシ、データセンターの接続経由の場合、接続ポリシーの除外条件が当てはまらない限り、自動拒否しきい値を下回るスコアであれば常にサインインが必要です。
4. その後、コミュニティはサービスに結果を確認し、国、IP リスク、接続タイプに関する独自のルールを適用します。

添付ファイルをアップロードする前に、クライアントは同じチェックを事前チェックとして実行できます。これにより、拒否されるはずの作成者のほとんどはアップロードせずに済みます。パブリケーションは公開時にもう一度チェックされるため、事前チェックに合格した後でも不合格になることがあります。

## リスクスコア

| シグナル               | 説明                                                                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| アカウントの年齢       | 新しいアカウントほどリスクスコアが高くなります。                                                                                     |
| カルマ                 | 蓄積されたコミュニティのカルマはリスクを下げます。                                                                                   |
| 作成者の評判           | バックグラウンドのインデクサーから得られるデータ。インデクサーは、各コミュニティでどの作成者が承認、削除、BAN されたかを追跡します。 |
| コンテンツとリンク     | 繰り返されるコンテンツを含む、テキストとリンクの分析。                                                                               |
| 速度                   | 同じ作成者による短時間の連続投稿はリスクを高めます。                                                                                 |
| IP インテリジェンス    | 接続タイプ (Tor、VPN、プロキシ、データセンター) と IP リスク。生の IP アドレスがコミュニティと共有されることはありません。           |
| リンクされたアカウント | 1 つのネットワークから多数のアカウントが投稿すると、リスクが段階的に上がります。                                                     |
| ソーシャル認証         | 作成者のアカウントでの過去のサインインはリスクを下げます。                                                                           |

## 検証

完了した各ステップがリスクスコアに乗算され、結果が 0.4 未満になるとパブリケーションは通過します。

| ステップ                               | 乗数         |
| -------------------------------------- | ------------ |
| CAPTCHA (Cloudflare Turnstile)         | × 0.7        |
| Google、Apple、Telegram でのサインイン | × 0.6        |
| 2 つ目の別のプロバイダーでのサインイン | さらに × 0.5 |

CAPTCHA で足りない場合は、続いてサインインが求められます。サインインで足りない場合は、CAPTCHA でチェックが完了するなら CAPTCHA が、そうでなければ 2 つ目のプロバイダーでのサインインが続きます。

### 記憶されたサインイン

サービスは、作成者が最後にサインインしたアカウントを記憶します。過去 30 日以内に作成者の投稿のいずれかでそのアカウントが使われていれば、検証が必要な以降の投稿では、作成者が再度サインインしたものとしてそのアカウントが再利用されます。再利用もそうした投稿に数えられるため、再利用のたびに 30 日の期間がリセットされます。それで足りる場合、投稿は CAPTCHA なしで通過します。アカウントに紐づくコミュニティでの BAN があるとこの仕組みは終了し、そのプロバイダーがサービスから削除された場合も同様です。

## 接続ポリシー

コミュニティは、Tor、VPN (iCloud Private Relay を含む)、プロキシ、データセンターの接続からのパブリケーションを制限できます。ホスト型サービスでは次のようになります。

- **VPN、プロキシ、データセンターの接続** からは、サインイン後に投稿できます。ページでは、サインインが必要な理由と、VPN をオフにしてサインインせずに投稿する方法を説明します。その後、コミュニティでの BAN はサインインに使用したアカウントにも適用されます。
- **実績のあるアカウント** は、VPN、プロキシ、データセンターの制限の対象外ですが、Tor の制限は対象となります。アカウントは、制限のない接続から別々の 3 日に CAPTCHA またはサインインを完了すると、実績のあるアカウントになります。CAPTCHA もサインインもなしで通過した投稿はカウントされません。1 つのネットワークがカウントされるのは 1 つのアカウントだけです。別のアカウントがそのネットワークからチェックに合格すると、そのネットワークはどちらのアカウントにもカウントされなくなります。それらのネットワークのいずれかでアカウントを BAN したコミュニティでは、この履歴は一切カウントされません。
- **Tor** は引き続き制限されます。ただし、コミュニティが設定した除外条件を持つ作成者は例外です。除外条件とは、モデレーターの役割、コミュニティのホワイトリスト、または検証済みの `.bso` 名です。

Forge Images にアップロードされる添付ファイルにも同じルールが適用されます。VPN、プロキシ、データセンターの接続経由の場合、アップロードにはサインインで合格した事前チェック、または実績のあるアカウントが必要です。Tor 経由の場合は、検証済みの除外条件が必要です。

## プライバシー

- **運営者** は、不正利用の検出のために生の IP アドレスとパブリケーションの内容を保存し、分類のために IP アドレスを外部のプロバイダー (デフォルトでは proxycheck.io) に送信します。
- **コミュニティ** が受け取るのは、国コード、IP リスク、接続タイプの推定、合否の結果のみです。生の IP やサインインに使われたアカウントを受け取ることはありません。
- **サインイン** ではプロフィールデータを要求しません。サービスが Google、Apple、Telegram から受け取るのはアカウント ID のみで、名前、メールアドレス、写真は受け取りません。ID は投稿とともに保存され、自動では削除されないため、BAN はアカウントにも適用されます。
- **VPN を使用している作成者** は、サインイン時も実際の IP アドレスを隠したままにできます。サービスに見えるのは VPN のアドレスだけです。

## レート制限

スコアリングの前に、サービスは投稿・返信・投票の 1 時間あたりまたは 1 日あたりの上限を超えた作成者を拒否します。上限はアカウントの年齢と良好な評判に応じて増え、BAN や削除があると減ります。

## API

主なルートは次のとおりです (`spamblocker.bitsocial.net/api/v1` からの相対パス)。

| ルート                   | 呼び出し元                        | 目的                                                       |
| ------------------------ | --------------------------------- | ---------------------------------------------------------- |
| `POST /evaluate`         | チャレンジの iframe、コミュニティ | パブリケーションをスコアリングし、そのセッションを作成する |
| `POST /challenge/verify` | コミュニティ                      | セッションの結果と IP インテリジェンスを読み取る           |
| `POST /precheck`         | 事前チェックの iframe             | アップロード前に下書きをスコアリングする                   |
| `GET /iframe/:sessionId` | 作成者のブラウザー                | 検証ページ                                                 |
| `POST /upload/authorize` | 作成者のクライアント              | Forge Images 用に添付ファイルを承認する                    |

リクエストの署名やレスポンスのスキーマを含む完全なコントラクトは、[spam-blocker の README](https://github.com/bitsocialnet/spam-blocker#api-contract) にあります。
