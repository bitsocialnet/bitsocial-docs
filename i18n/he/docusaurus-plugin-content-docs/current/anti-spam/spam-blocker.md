# Spam Blocker

Spam Blocker מעניק לפוסטים, לתגובות ולהצבעות ציון סיכון לספאם לפני שקהילה מקבלת אותם. הקהילה מתקינה את חבילת האתגר, ששולחת כל פרסום לשירות Spam Blocker. Bitsocial מפעילה שירות כזה בכתובת `spamblocker.bitsocial.net`.

- **`@bitsocial/spam-blocker-challenge`** היא חבילת האתגר בקוד פתוח שקהילות מתקינות. חוזה האינטגרציה, הסכמות המשותפות וה-API שלה ציבוריים.
- **השירות המתארח** מנקד את הפרסומים ומגיש את דפי ה-CAPTCHA וההתחברות. המשקלים וההיוריסטיקות המפורטים שלו אינם ציבוריים, כמוסבר ב[מדיניות קוד המקור](https://github.com/bitsocialnet/spam-blocker/blob/master/docs/architecture/hosted-service-source-policy.md).

**קוד מקור:** [github.com/bitsocialnet/spam-blocker](https://github.com/bitsocialnet/spam-blocker)

## כיצד נבדק פרסום

1. האתגר של הקהילה שולח את הפרסום החתום לשירות, שמחזיר ציון סיכון בין 0 ל-1.
2. מתחת לסף הקבלה האוטומטית של הקהילה, הפרסום עובר. בסף הדחייה האוטומטית שלה או מעליו, הוא נכשל והמחבר רואה מדוע.
3. בטווח שביניהם, נעשה שימוש חוזר בהתחברות הזכורה של המחבר כשהיא מספיקה. אחרת המחבר מקבל דף אימות: CAPTCHA כאשר CAPTCHA לבדו יכול להספיק למעבר, או התחברות. דרך חיבור VPN, פרוקסי או מרכז נתונים שהקהילה מגבילה, המחבר צריך התחברות בכל ציון שמתחת לסף הדחייה האוטומטית, אלא אם חל פטור המפורט תחת מדיניות חיבורים.
4. לאחר מכן הקהילה בודקת את התוצאה מול השירות ומחילה כללים משלה לגבי מדינה, סיכון IP וסוג חיבור.

לפני העלאת קובץ מצורף, לקוח יכול להריץ את אותה בדיקה כבדיקה מקדימה, וכך נחסכת ההעלאה מרוב המחברים שהיו נדחים. הפרסום נבדק שוב כשהוא מתפרסם, ולכן הוא עדיין יכול להיכשל גם אחרי שהבדיקה המקדימה עברה.

## ציון סיכון

| אות             | תיאור                                                                                                   |
| --------------- | ------------------------------------------------------------------------------------------------------- |
| גיל חשבון       | חשבונות חדשים יותר מקבלים ציוני סיכון גבוהים יותר.                                                      |
| קארמה           | קארמה קהילתית מצטברת מפחיתה סיכון.                                                                      |
| מוניטין מחבר    | נתונים מאינדקסר שפועל ברקע ועוקב אחר אילו מחברים מתקבלים, מוסרים או נחסמים בקהילות השונות.              |
| תוכן וקישורים   | ניתוח טקסט וקישורים, כולל תוכן חוזר.                                                                    |
| מהירות          | פוסטים רצופים במהירות מאותו מחבר מגדילים את הסיכון.                                                     |
| מודיעין IP      | סוג החיבור (Tor, VPN, פרוקסי, מרכז נתונים) וסיכון ה-IP. כתובות IP גולמיות לעולם אינן משותפות עם קהילות. |
| חשבונות מקושרים | חשבונות רבים שמפרסמים מאותה רשת מעלים את הסיכון בהדרגה.                                                 |
| אימות חברתי     | התחברויות קודמות בחשבון של המחבר מורידות את הסיכון.                                                     |

## אימות

כל שלב שהושלם מכפיל את ציון הסיכון, והפרסום עובר כשהתוצאה נמוכה מ-0.4.

| שלב                                  | מכפיל      |
| ------------------------------------ | ---------- |
| CAPTCHA (Cloudflare Turnstile)       | × 0.7      |
| התחברות עם Google, Apple או Telegram | × 0.6      |
| התחברות עם ספק שני ושונה             | × 0.5 נוסף |

אחרי CAPTCHA שאינו מספיק מגיעה התחברות. אחרי התחברות שאינה מספיקה מגיע CAPTCHA אם הוא משלים את הבדיקה, ואחרת התחברות עם ספק שני.

### התחברויות זכורות

השירות זוכר את החשבון שבו המחבר התחבר לאחרונה. פוסט מאוחר יותר שדורש אימות משתמש בו שוב, כאילו המחבר התחבר מחדש, כאשר אחד מהפוסטים של המחבר השתמש בו ב-30 הימים האחרונים. שימוש חוזר נחשב לפוסט כזה, ולכן ספירת 30 הימים מתחילה מחדש בכל שימוש חוזר. כשזה מספיק, הפוסט עובר בלי CAPTCHA. חסימה בקהילה, כשהיא מקושרת לחשבון, מסיימת זאת, וכך גם הסרת הספק שלו מהשירות.

## מדיניות חיבורים

קהילות יכולות להגביל פרסומים מחיבורי Tor, VPN (כולל iCloud Private Relay), פרוקסי ומרכזי נתונים. בשירות המתארח:

- **חיבורי VPN, פרוקסי ומרכזי נתונים** יכולים לפרסם לאחר התחברות. הדף מסביר מדוע נדרשת התחברות וכיצד אפשר לפרסם בלעדיה על ידי כיבוי ה-VPN. מאותו רגע, חסימה בקהילה חלה גם על החשבון שבו נעשתה ההתחברות.
- **חשבונות מבוססים** פטורים מההגבלות על VPN, פרוקסי ומרכזי נתונים, אך לא מההגבלה על Tor. חשבון נעשה מבוסס לאחר שעבר CAPTCHA או התחברות ב-3 ימים נפרדים מחיבורים שאינם מוגבלים; פוסטים שעברו בלי אף אחד מהם אינם נספרים. רשת נספרת לטובת חשבון אחד בלבד: ברגע שחשבון אחר עובר בדיקה ממנה, היא אינה נספרת לאף אחד מהם. בקהילה שחסמה חשבון באחת מהרשתות האלה, שום חלק מההיסטוריה הזו אינו נספר.
- **Tor** נשאר מוגבל, למעט מחברים עם פטור שהקהילה הגדירה: תפקיד מודרטור, הרשימה הלבנה של הקהילה, או שם `.bso` מאומת.

קבצים מצורפים שמועלים ל-Forge Images כפופים לאותם כללים. דרך חיבור VPN, פרוקסי או מרכז נתונים, ההעלאה דורשת בדיקה מקדימה שעברה עם התחברות, או חשבון מבוסס. דרך Tor, היא דורשת פטור מאומת.

## פרטיות

- **המפעיל** שומר כתובות IP גולמיות ותוכן פרסומים לצורך זיהוי שימוש לרעה, ושולח כתובות IP לספק צד שלישי לצורך סיווג (proxycheck.io כברירת מחדל).
- **קהילות** מקבלות רק את קוד המדינה, סיכון ה-IP, הערכת סוג החיבור ואת התוצאה, עבר או נכשל. הן לעולם אינן מקבלות את כתובת ה-IP הגולמית או את החשבון שבו נעשתה ההתחברות.
- **התחברויות** אינן מבקשות נתוני פרופיל. השירות מקבל רק מזהה חשבון מ-Google, Apple או Telegram, לעולם לא שם, אימייל או תמונה. הוא שומר את המזהה יחד עם הפוסט, ללא מחיקה אוטומטית, כך שחסימה חלה גם על החשבון.
- **מחברים שמשתמשים ב-VPN** שומרים את כתובת ה-IP האמיתית שלהם מוסתרת כשהם מתחברים: השירות רואה רק את הכתובת של ה-VPN.

## הגבלת קצב

לפני הניקוד, השירות דוחה מחברים שחורגים מהמכסה השעתית או היומית שלהם לפוסטים, לתגובות ולהצבעות. המכסות גדלות עם גיל החשבון ומוניטין טוב, וקטנות לאחר חסימות או הסרות.

## API

הנתיבים העיקריים, ביחס ל-`spamblocker.bitsocial.net/api/v1`:

| נתיב                     | גורם קורא                  | מטרה                               |
| ------------------------ | -------------------------- | ---------------------------------- |
| `POST /evaluate`         | ה-iframe של האתגר, קהילה   | ניקוד פרסום ויצירת הסשן שלו        |
| `POST /challenge/verify` | קהילה                      | קריאת תוצאת הסשן ומודיעין ה-IP     |
| `POST /precheck`         | ה-iframe של הבדיקה המקדימה | ניקוד טיוטה לפני העלאה             |
| `GET /iframe/:sessionId` | הדפדפן של המחבר            | דף אימות                           |
| `POST /upload/authorize` | הלקוח של המחבר             | אישור קובץ מצורף עבור Forge Images |

החוזה המלא, כולל חתימת בקשות וסכמות תגובה, נמצא ב[README של spam-blocker](https://github.com/bitsocialnet/spam-blocker#api-contract).
