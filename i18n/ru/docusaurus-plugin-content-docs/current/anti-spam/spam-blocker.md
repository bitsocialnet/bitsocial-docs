# Spam Blocker

Spam Blocker оценивает посты, ответы и голоса на риск спама до того, как сообщество их примет. Сообщество устанавливает пакет проверки, который отправляет каждую публикацию в сервис защиты от спама. Bitsocial поддерживает один такой сервис по адресу `spamblocker.bitsocial.net`.

- **`@bitsocial/spam-blocker-challenge`** — пакет проверки с открытым исходным кодом, который устанавливают сообщества. Его контракт интеграции, общие схемы и API открыты.
- **Размещённый сервис** оценивает публикации и отдаёт страницы CAPTCHA и входа. Подробные веса и эвристики сервиса закрыты, как объясняет [политика в отношении исходного кода](https://github.com/bitsocialnet/spam-blocker/blob/master/docs/architecture/hosted-service-source-policy.md).

**Исходный код:** [github.com/bitsocialnet/spam-blocker](https://github.com/bitsocialnet/spam-blocker)

## Как проверяется публикация

1. Проверка сообщества отправляет подписанную публикацию в сервис, и тот возвращает оценку риска от 0 до 1.
2. Если оценка ниже порога автоприёма сообщества, публикация проходит. Если она достигает порога автоотклонения или выше его, публикация отклоняется, и автор видит причину.
3. В промежутке между порогами повторно используется запомненный вход автора, если его достаточно. Иначе автор получает страницу верификации: CAPTCHA, если одной CAPTCHA может хватить, или вход в аккаунт. При подключении через VPN, прокси или из дата-центра, которое сообщество ограничивает, автору нужен вход при любой оценке ниже порога автоотклонения, если не действует исключение из раздела Правила для подключений.
4. Затем сообщество сверяет результат с сервисом и применяет собственные правила по стране, риску IP и типу подключения.

Перед загрузкой прикреплённого файла клиент может выполнить ту же проверку как предварительную, что избавляет от загрузки большинство авторов, которых бы отклонили. Публикация проверяется ещё раз, когда её публикуют, поэтому её всё равно могут отклонить, даже если предварительная проверка пройдена.

## Оценка риска

| Сигнал                 | Описание                                                                                                           |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Возраст аккаунта       | Чем новее аккаунт, тем выше оценка риска.                                                                          |
| Карма                  | Накопленная карма в сообществе снижает риск.                                                                       |
| Репутация автора       | Данные фонового индексатора, который отслеживает, каких авторов принимают, удаляют или банят в разных сообществах. |
| Содержимое и ссылки    | Анализ текста и ссылок, включая повторяющееся содержимое.                                                          |
| Частота публикаций     | Быстрые публикации подряд от одного автора повышают риск.                                                          |
| Данные об IP           | Тип подключения (Tor, VPN, прокси, дата-центр) и риск IP. Сами IP-адреса сообществам не передаются.                |
| Связанные аккаунты     | Если из одной сети публикует много аккаунтов, риск постепенно растёт.                                              |
| Социальная верификация | Прежние входы, привязанные к аккаунту автора, снижают риск.                                                        |

## Верификация

Каждый пройденный шаг умножает оценку риска, и публикация проходит, когда результат становится ниже 0.4.

| Шаг                                    | Множитель |
| -------------------------------------- | --------- |
| CAPTCHA (Cloudflare Turnstile)         | × 0.7     |
| Вход через Google, Apple или Telegram  | × 0.6     |
| Вход через второго, другого провайдера | ещё × 0.5 |

Если CAPTCHA недостаточно, за ней следует вход. Если недостаточно входа, за ним следует CAPTCHA, когда она завершает проверку, а иначе вход через второго провайдера.

### Запомненные входы

Сервис запоминает аккаунт, через который автор входил в последний раз. Следующий пост, которому нужна верификация, снова использует этот аккаунт, как если бы автор вошёл заново, если один из постов автора использовал его за последние 30 дней. Повторное использование тоже считается таким постом, поэтому 30 дней отсчитываются заново с каждым из них. Если этого достаточно, пост проходит без CAPTCHA. Это прекращается, если в сообществе появляется бан, связанный с этим аккаунтом, а также если провайдер аккаунта удалён из сервиса.

## Правила для подключений

Сообщества могут ограничивать публикации через Tor, VPN (включая iCloud Private Relay), прокси и подключения из дата-центров. В размещённом сервисе:

- **Подключения через VPN, прокси и из дата-центров** могут публиковать после входа. Страница объясняет, зачем нужен вход и как опубликовать без него, отключив VPN. Бан в сообществе после этого распространяется и на аккаунт, через который выполнен вход.
- **Устоявшиеся аккаунты** освобождены от ограничений для VPN, прокси и дата-центров, но не от ограничения для Tor. Аккаунт становится устоявшимся, когда пройдёт CAPTCHA или вход в 3 разных дня с неограниченных подключений; посты, прошедшие без них, не учитываются. Сеть учитывается только для одного аккаунта: как только с неё проходит проверку другой аккаунт, она не учитывается ни для одного из них. В сообществе, которое забанило аккаунт в одной из этих сетей, эта история не учитывается вовсе.
- **Tor** остаётся ограниченным, кроме авторов с исключением, которое настроило сообщество: роль модератора, белый список сообщества или подтверждённое имя `.bso`.

Прикреплённые файлы, загружаемые в Forge Images, подчиняются тем же правилам. Через VPN, прокси или подключение из дата-центра для загрузки нужна предварительная проверка, пройденная со входом, или устоявшийся аккаунт. Через Tor нужно подтверждённое исключение.

## Приватность

- **Оператор** хранит сами IP-адреса и содержимое публикаций для выявления злоупотреблений и отправляет IP-адреса стороннему провайдеру для классификации (по умолчанию proxycheck.io).
- **Сообщества** получают только код страны, риск IP, предполагаемый тип подключения и результат: пройдено или нет. Сам IP-адрес и аккаунт, через который выполнен вход, они не получают никогда.
- **Вход в аккаунт** не запрашивает данные профиля. Сервис получает от Google, Apple или Telegram только ID аккаунта, но никогда имя, почту или фото. Он хранит этот ID вместе с постом без автоматического удаления, поэтому бан распространяется и на аккаунт.
- **Авторы, использующие VPN**, при входе не раскрывают свой настоящий IP-адрес: сервис видит только адрес VPN.

## Ограничение частоты

Ещё до оценки сервис отклоняет авторов, превысивших свой часовой или суточный лимит на посты, ответы и голоса. Лимиты растут с возрастом аккаунта и хорошей репутацией и сокращаются после банов или удалений.

## API

Основные маршруты относительно `spamblocker.bitsocial.net/api/v1`:

| Маршрут                  | Кто вызывает                    | Назначение                                       |
| ------------------------ | ------------------------------- | ------------------------------------------------ |
| `POST /evaluate`         | iframe проверки, сообщество     | Оценить публикацию и создать для неё сессию      |
| `POST /challenge/verify` | Сообщество                      | Получить итог сессии и данные об IP              |
| `POST /precheck`         | iframe предварительной проверки | Оценить черновик до загрузки                     |
| `GET /iframe/:sessionId` | Браузер автора                  | Страница верификации                             |
| `POST /upload/authorize` | Клиент автора                   | Авторизовать прикреплённый файл для Forge Images |

Полный контракт, включая подпись запросов и схемы ответов, описан в [README spam-blocker](https://github.com/bitsocialnet/spam-blocker#api-contract).
