# Spam Blocker

Spam Blocker ให้คะแนนความเสี่ยงด้านสแปมแก่โพสต์ การตอบกลับ และการโหวต ก่อนที่ชุมชนจะยอมรับ ชุมชนติดตั้งแพ็กเกจความท้าทาย ซึ่งจะส่งเนื้อหาแต่ละชิ้นไปยังบริการ Spam Blocker โดย Bitsocial ให้บริการไว้หนึ่งแห่งที่ `spamblocker.bitsocial.net`

- **`@bitsocial/spam-blocker-challenge`** คือแพ็กเกจความท้าทายแบบโอเพนซอร์สที่ชุมชนนำไปติดตั้ง ข้อกำหนดการผสานรวม สคีมาที่ใช้ร่วมกัน และ API ของแพ็กเกจนี้เปิดเป็นสาธารณะ
- **บริการแบบโฮสต์** ให้คะแนนเนื้อหาและให้บริการหน้า CAPTCHA กับหน้าลงชื่อเข้าใช้ ค่าน้ำหนักและฮิวริสติกโดยละเอียดของบริการนี้ไม่เปิดเผย ตามที่ [นโยบายซอร์สโค้ด](https://github.com/bitsocialnet/spam-blocker/blob/master/docs/architecture/hosted-service-source-policy.md) อธิบายไว้

**ซอร์สโค้ด:** [github.com/bitsocialnet/spam-blocker](https://github.com/bitsocialnet/spam-blocker)

## เนื้อหาถูกตรวจสอบอย่างไร

1. ความท้าทายของชุมชนส่งเนื้อหาที่ลงนามแล้วไปยังบริการ ซึ่งจะส่งคะแนนความเสี่ยงระหว่าง 0 ถึง 1 กลับมา
2. หากต่ำกว่าเกณฑ์ยอมรับอัตโนมัติของชุมชน เนื้อหาจะผ่าน หากเท่ากับหรือสูงกว่าเกณฑ์ปฏิเสธอัตโนมัติ เนื้อหาจะไม่ผ่านและผู้เขียนจะเห็นเหตุผล
3. หากอยู่ระหว่างสองเกณฑ์นี้ ระบบจะใช้การลงชื่อเข้าใช้ของผู้เขียนในช่วง 30 วันที่ผ่านมาซ้ำหากเพียงพอ มิฉะนั้นผู้เขียนจะได้รับหน้ายืนยัน: CAPTCHA เมื่อ CAPTCHA อย่างเดียวผ่านได้ หรือไม่ก็การลงชื่อเข้าใช้
4. จากนั้นชุมชนจะตรวจสอบผลลัพธ์กับบริการ และใช้กฎของตนเองเกี่ยวกับประเทศ ความเสี่ยงของ IP และประเภทการเชื่อมต่อ

ก่อนอัปโหลดไฟล์แนบ ไคลเอ็นต์สามารถเรียกใช้การตรวจสอบเดียวกันนี้เป็นการตรวจล่วงหน้าได้ ผู้เขียนที่จะถูกปฏิเสธจึงไม่ต้องอัปโหลดเลย

## คะแนนความเสี่ยง

| สัญญาณ                  | รายละเอียด                                                                                                     |
| ----------------------- | -------------------------------------------------------------------------------------------------------------- |
| อายุของบัญชี            | บัญชีที่เพิ่งสร้างใหม่จะได้คะแนนความเสี่ยงสูงกว่า                                                              |
| คะแนน Karma             | Karma ที่สะสมไว้ในชุมชนช่วยลดความเสี่ยงลง                                                                      |
| ชื่อเสียงของผู้เขียน    | ข้อมูลจากตัวจัดทำดัชนีเบื้องหลังที่ติดตามว่าผู้เขียนคนใดได้รับการยอมรับ ถูกลบเนื้อหา หรือถูกแบนในชุมชนต่าง ๆ   |
| เนื้อหาและลิงก์         | การวิเคราะห์ข้อความและลิงก์ รวมถึงเนื้อหาที่ซ้ำกัน                                                             |
| ความถี่ในการโพสต์       | การโพสต์ติด ๆ กันอย่างรวดเร็วจากผู้เขียนคนเดียวกันทำให้ความเสี่ยงสูงขึ้น                                       |
| ข้อมูลข่าวกรองเรื่อง IP | ประเภทการเชื่อมต่อ (Tor, VPN, พร็อกซี, ดาต้าเซ็นเตอร์) และความเสี่ยงของ IP ที่อยู่ IP ดิบไม่เคยถูกแชร์ให้ชุมชน |
| บัญชีที่เชื่อมโยงกัน    | ยิ่งมีบัญชีจำนวนมากโพสต์จากเครือข่ายเดียวกัน ความเสี่ยงก็ยิ่งเพิ่มขึ้นตามลำดับ                                 |
| การยืนยันทางโซเชียล     | การลงชื่อเข้าใช้ครั้งก่อน ๆ บนบัญชีของผู้เขียนช่วยลดความเสี่ยง                                                 |

## การยืนยัน

แต่ละขั้นตอนที่ทำสำเร็จจะคูณคะแนนความเสี่ยงด้วยตัวคูณ และเนื้อหาจะผ่านเมื่อผลลัพธ์ต่ำกว่า 0.4

| ขั้นตอน                                                 | ตัวคูณ    |
| ------------------------------------------------------- | --------- |
| CAPTCHA (Cloudflare Turnstile)                          | × 0.7     |
| ลงชื่อเข้าใช้ด้วย Google, Apple หรือ Telegram           | × 0.6     |
| ลงชื่อเข้าใช้ด้วยผู้ให้บริการรายที่สองซึ่งต่างจากรายแรก | อีก × 0.5 |

หาก CAPTCHA ยังไม่เพียงพอ ขั้นต่อไปคือการลงชื่อเข้าใช้ หากการลงชื่อเข้าใช้ยังไม่เพียงพอ ขั้นต่อไปคือ CAPTCHA ในกรณีที่ CAPTCHA ทำให้การตรวจสอบเสร็จสิ้นได้ มิฉะนั้นจะเป็นการลงชื่อเข้าใช้กับผู้ให้บริการรายที่สอง

### การลงชื่อเข้าใช้ที่ระบบจดจำไว้

บริการจะจดจำบัญชีที่ผู้เขียนใช้ลงชื่อเข้าใช้ครั้งล่าสุด โพสต์ถัดไปที่ต้องยืนยันจะใช้บัญชีนั้นซ้ำ เสมือนว่าผู้เขียนได้ลงชื่อเข้าใช้อีกครั้ง ตราบใดที่ผู้เขียนยังโพสต์ด้วยบัญชีนั้นอย่างน้อยหนึ่งครั้งทุก 30 วัน เมื่อเพียงพอแล้ว โพสต์จะผ่านโดยไม่ต้องทำ CAPTCHA หากชุมชนแบนโดยผูกการแบนไว้กับบัญชีนั้น การจดจำนี้จะสิ้นสุดลง และจะสิ้นสุดเช่นกันหากผู้ให้บริการของบัญชีนั้นถูกนำออกจากบริการ

## นโยบายการเชื่อมต่อ

ชุมชนสามารถจำกัดเนื้อหาที่มาจากการเชื่อมต่อผ่าน Tor, VPN (รวมถึง iCloud Private Relay), พร็อกซี และดาต้าเซ็นเตอร์ได้ ในบริการแบบโฮสต์:

- **การเชื่อมต่อผ่าน VPN, พร็อกซี และดาต้าเซ็นเตอร์** โพสต์ได้หลังจากลงชื่อเข้าใช้ หน้ายืนยันจะอธิบายว่าทำไมต้องลงชื่อเข้าใช้ และจะโพสต์โดยไม่ต้องลงชื่อเข้าใช้ได้อย่างไรด้วยการปิด VPN จากนั้นการแบนในชุมชนจะมีผลกับบัญชีที่ใช้ลงชื่อเข้าใช้ด้วย
- **บัญชีที่อยู่มานาน** ซึ่งผ่านการตรวจสอบใน 3 วันที่แตกต่างกันจากการเชื่อมต่อที่ไม่ถูกจำกัด จะได้รับการยกเว้น
- **Tor** ยังคงถูกจำกัด ยกเว้นผู้เขียนที่มีข้อยกเว้นซึ่งชุมชนตั้งค่าไว้: บทบาทผู้ดูแล ไวต์ลิสต์ของชุมชน หรือชื่อ `.bso` ที่ยืนยันแล้ว

ไฟล์แนบที่อัปโหลดไปยัง Forge Images ใช้กฎเดียวกัน หากอัปโหลดผ่านการเชื่อมต่อแบบ VPN, พร็อกซี หรือดาต้าเซ็นเตอร์ ต้องมีการตรวจล่วงหน้าที่ผ่านด้วยการลงชื่อเข้าใช้ หรือเป็นบัญชีที่อยู่มานาน หากอัปโหลดผ่าน Tor ต้องมีข้อยกเว้นที่ยืนยันแล้ว

## ความเป็นส่วนตัว

- **ผู้ดำเนินการบริการ** จัดเก็บที่อยู่ IP ดิบและเนื้อหาที่เผยแพร่ไว้เพื่อตรวจจับการใช้งานในทางที่ผิด และส่งที่อยู่ IP ไปยังผู้ให้บริการภายนอกเพื่อจัดประเภท (ค่าเริ่มต้นคือ proxycheck.io)
- **ชุมชน** ได้รับเพียงรหัสประเทศ ความเสี่ยงของ IP ประเภทการเชื่อมต่อโดยประมาณ และผลว่าผ่านหรือไม่ผ่าน ชุมชนไม่เคยได้รับ IP ดิบหรือบัญชีที่ใช้ลงชื่อเข้าใช้
- **การลงชื่อเข้าใช้** ไม่ขอข้อมูลโปรไฟล์ใด ๆ บริการได้รับเพียง ID บัญชีจาก Google, Apple หรือ Telegram ไม่เคยได้รับชื่อ อีเมล หรือรูปภาพ บริการเก็บ ID ไว้คู่กับโพสต์โดยไม่มีการลบอัตโนมัติ เพื่อให้การแบนมีผลกับบัญชีนั้นด้วย
- **ผู้เขียนที่ใช้ VPN** ยังคงซ่อนที่อยู่ IP จริงไว้ได้เมื่อลงชื่อเข้าใช้: บริการเห็นเพียงที่อยู่ของ VPN

## การจำกัดอัตราการเรียกใช้

ก่อนให้คะแนน บริการจะปฏิเสธผู้เขียนที่ใช้โควตารายชั่วโมงหรือรายวันสำหรับโพสต์ การตอบกลับ และการโหวตเกินกำหนด โควตาจะเพิ่มขึ้นตามอายุบัญชีและชื่อเสียงที่ดี และลดลงหลังถูกแบนหรือถูกลบเนื้อหา

## API

เส้นทางหลัก โดยอ้างอิงจาก `spamblocker.bitsocial.net/api/v1`:

| เส้นทาง                  | ผู้เรียก                 | วัตถุประสงค์                                   |
| ------------------------ | ------------------------ | ---------------------------------------------- |
| `POST /evaluate`         | iframe ความท้าทาย, ชุมชน | ให้คะแนนเนื้อหาและสร้างเซสชันของเนื้อหานั้น    |
| `POST /challenge/verify` | ชุมชน                    | อ่านผลลัพธ์ของเซสชันและข้อมูลข่าวกรองเรื่อง IP |
| `POST /precheck`         | iframe การตรวจล่วงหน้า   | ให้คะแนนฉบับร่างก่อนอัปโหลด                    |
| `GET /iframe/:sessionId` | เบราว์เซอร์ของผู้เขียน   | หน้ายืนยัน                                     |
| `POST /upload/authorize` | ไคลเอ็นต์ของผู้เขียน     | อนุญาตไฟล์แนบสำหรับ Forge Images               |

ข้อกำหนดฉบับเต็ม รวมถึงการลงนามคำขอและสคีมาของการตอบกลับ อยู่ใน [README ของ spam-blocker](https://github.com/bitsocialnet/spam-blocker#api-contract)
