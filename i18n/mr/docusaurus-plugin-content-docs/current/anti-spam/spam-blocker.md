# Spam Blocker

एखादा समुदाय पोस्ट, उत्तरे आणि मते स्वीकारण्यापूर्वी Spam Blocker त्यांच्या स्पॅम जोखमीचा स्कोअर ठरवते. समुदाय आव्हान पॅकेज इन्स्टॉल करतो, जे प्रत्येक प्रकाशन स्पॅम ब्लॉकर सेवेकडे पाठवते. Bitsocial अशी एक सेवा `spamblocker.bitsocial.net` येथे चालवते.

- **`@bitsocial/spam-blocker-challenge`** हे समुदाय इन्स्टॉल करतात ते मुक्त-स्रोत आव्हान पॅकेज आहे. त्याचा एकत्रीकरण करार, सामायिक स्कीमा आणि API सार्वजनिक आहेत.
- **होस्ट केलेली सेवा** प्रकाशनांचा स्कोअर ठरवते आणि CAPTCHA व साइन-इन पृष्ठे पुरवते. [स्रोत धोरण](https://github.com/bitsocialnet/spam-blocker/blob/master/docs/architecture/hosted-service-source-policy.md) स्पष्ट करते त्याप्रमाणे, तिचे तपशीलवार भार आणि हेरिस्टिक्स खाजगी आहेत.

**स्रोत कोड:** [github.com/bitsocialnet/spam-blocker](https://github.com/bitsocialnet/spam-blocker)

## प्रकाशन कसे तपासले जाते

1. समुदायाचे आव्हान स्वाक्षरी केलेले प्रकाशन सेवेकडे पाठवते, आणि सेवा 0 ते 1 दरम्यानचा जोखीम स्कोअर परत करते.
2. स्कोअर समुदायाच्या स्वयं-स्वीकार थ्रेशोल्डपेक्षा कमी असल्यास प्रकाशन उत्तीर्ण होते. तो स्वयं-नकार थ्रेशोल्डइतका किंवा त्याहून जास्त असल्यास प्रकाशन अयशस्वी होते आणि लेखकाला त्याचे कारण दिसते.
3. या दोन्हींच्या दरम्यान, लेखकाचे मागील 30 दिवसांतील साइन-इन पुरेसे असल्यास ते पुन्हा वापरले जाते. अन्यथा लेखकाला पडताळणी पृष्ठ मिळते: केवळ CAPTCHA ने उत्तीर्ण होणे शक्य असल्यास CAPTCHA, नाहीतर साइन-इन.
4. त्यानंतर समुदाय सेवेकडून निकाल तपासतो आणि देश, IP जोखीम आणि कनेक्शन प्रकार यांसाठी स्वतःचे नियम लागू करतो.

संलग्न फाइल अपलोड करण्यापूर्वी क्लायंट हीच तपासणी पूर्व-तपासणी म्हणून चालवू शकतो, त्यामुळे नाकारले जाणारे लेखक कधीच अपलोड करत नाहीत.

## जोखीम स्कोअर

| सिग्नल           | वर्णन                                                                                                                                              |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| खाते वय          | नवीन खात्यांना उच्च जोखीम स्कोअर मिळतात.                                                                                                           |
| कर्म             | संचित सामुदायिक कर्मामुळे धोका कमी होतो.                                                                                                           |
| लेखक प्रतिष्ठा   | पार्श्वभूमीत चालणाऱ्या इंडेक्सरचा डेटा, जो समुदायांमध्ये कोणते लेखक स्वीकारले जातात, काढून टाकले जातात किंवा बंदीला सामोरे जातात याचा मागोवा घेतो. |
| सामग्री आणि लिंक | पुनरावृत्त सामग्रीसह मजकूर आणि लिंक विश्लेषण.                                                                                                      |
| वेग              | एकाच लेखकाच्या जलद सलग पोस्टमुळे धोका वाढतो.                                                                                                       |
| IP बुद्धिमत्ता   | कनेक्शन प्रकार (Tor, VPN, प्रॉक्सी, डेटासेंटर) आणि IP जोखीम. कच्चे IP पत्ते समुदायांसह कधीही सामायिक केले जात नाहीत.                               |
| जोडलेली खाती     | एकाच नेटवर्कवरून अनेक खाती पोस्ट करत असल्यास जोखीम हळूहळू वाढते.                                                                                   |
| सामाजिक पडताळणी  | लेखकाच्या खात्यावरील आधीचे साइन-इन जोखीम कमी करतात.                                                                                                |

## पडताळणी

प्रत्येक पूर्ण झालेली पायरी जोखीम स्कोअरला एका गुणकाने गुणते, आणि निकाल 0.4 पेक्षा कमी झाल्यावर प्रकाशन उत्तीर्ण होते.

| पायरी                                       | गुणक       |
| ------------------------------------------- | ---------- |
| CAPTCHA (Cloudflare Turnstile)              | × 0.7      |
| Google, Apple किंवा Telegram द्वारे साइन-इन | × 0.6      |
| दुसऱ्या, वेगळ्या प्रदात्याद्वारे साइन-इन    | आणखी × 0.5 |

CAPTCHA पुरेसा नसल्यास त्यानंतर साइन-इन करावे लागते. साइन-इन पुरेसे नसल्यास, CAPTCHA ने तपासणी पूर्ण होत असेल तर त्यानंतर CAPTCHA येतो, अन्यथा दुसऱ्या प्रदात्याद्वारे साइन-इन.

### लक्षात ठेवलेले साइन-इन

लेखकाने शेवटचे ज्या खात्याने साइन-इन केले होते, ते खाते सेवा लक्षात ठेवते. नंतरच्या ज्या पोस्टला पडताळणी लागते, ती हे खाते पुन्हा वापरते, जणू लेखकाने पुन्हा साइन-इन केले आहे, जोपर्यंत लेखक त्या खात्याने किमान दर 30 दिवसांत एकदा पोस्ट करत राहतो. ते पुरेसे असल्यास पोस्ट CAPTCHA शिवाय उत्तीर्ण होते. समुदायात त्या खात्याशी जोडलेली बंदी आल्यास हे थांबते, आणि सेवेतून त्या खात्याचा प्रदाता काढून टाकल्यासही हे थांबते.

## कनेक्शन धोरणे

समुदाय Tor, VPN (iCloud Private Relay सह), प्रॉक्सी आणि डेटासेंटर कनेक्शनमधून येणारी प्रकाशने प्रतिबंधित करू शकतात. होस्ट केलेल्या सेवेवर:

- **VPN, प्रॉक्सी आणि डेटासेंटर कनेक्शन** साइन-इननंतर पोस्ट करू शकतात. साइन-इन का आवश्यक आहे आणि VPN बंद करून साइन-इनशिवाय कसे पोस्ट करायचे, हे पृष्ठ स्पष्ट करते. त्यानंतर समुदायातील बंदी साइन-इनसाठी वापरलेल्या खात्यालाही लागू होते.
- **प्रस्थापित खात्यांना**, म्हणजे ज्यांनी अप्रतिबंधित कनेक्शनवरून 3 वेगवेगळ्या दिवशी तपासणी उत्तीर्ण केली आहे अशा खात्यांना, सूट आहे.
- **Tor** प्रतिबंधितच राहते, मात्र समुदायाने कॉन्फिगर केलेली सूट असलेले लेखक याला अपवाद आहेत: मॉडरेटर भूमिका, समुदायाची व्हाइटलिस्ट किंवा पडताळलेले `.bso` नाव.

Forge Images वर अपलोड केलेल्या संलग्न फाइलींना हेच नियम लागू होतात. VPN, प्रॉक्सी किंवा डेटासेंटर कनेक्शनद्वारे अपलोड करण्यासाठी साइन-इनसह उत्तीर्ण झालेली पूर्व-तपासणी किंवा प्रस्थापित खाते आवश्यक आहे. Tor द्वारे अपलोड करण्यासाठी पडताळलेली सूट आवश्यक आहे.

## गोपनीयता

- **सेवा चालक** गैरवापर ओळखण्यासाठी कच्चे IP पत्ते आणि प्रकाशनांची सामग्री संग्रहित करतो, आणि वर्गीकरणासाठी IP पत्ते तृतीय-पक्ष प्रदात्याकडे पाठवतो (डीफॉल्टनुसार proxycheck.io).
- **समुदायांना** फक्त देश कोड, IP जोखीम, कनेक्शन प्रकाराचा अंदाज आणि उत्तीर्ण किंवा अयशस्वी निकाल मिळतो. त्यांना कच्चा IP किंवा साइन-इन खाते कधीही मिळत नाही.
- **साइन-इन** कोणताही प्रोफाइल डेटा मागत नाहीत. सेवेला Google, Apple किंवा Telegram कडून फक्त खाते ID मिळतो; नाव, ईमेल किंवा फोटो कधीही मिळत नाही. सेवा हा ID पोस्टसोबत कोणत्याही स्वयंचलित हटवण्याशिवाय ठेवते, त्यामुळे बंदी त्या खात्यालाही लागू होते.
- **VPN वापरणाऱ्या लेखकांचा** खरा IP पत्ता साइन-इन करतानाही लपलेलाच राहतो: सेवेला फक्त VPN चा पत्ता दिसतो.

## दर मर्यादा

स्कोअरिंगपूर्वी, पोस्ट, उत्तरे आणि मतांसाठीचे तासाचे किंवा दैनिक बजेट ओलांडणाऱ्या लेखकांना सेवा नाकारते. बजेट खात्याच्या वयासह आणि चांगल्या प्रतिष्ठेसह वाढते, आणि बंदी किंवा काढून टाकल्यानंतर कमी होते.

## API

मुख्य रूट्स, `spamblocker.bitsocial.net/api/v1` च्या सापेक्ष:

| रूट                      | कॉलर                  | उद्देश                                            |
| ------------------------ | --------------------- | ------------------------------------------------- |
| `POST /evaluate`         | आव्हान iframe, समुदाय | प्रकाशनाचा स्कोअर ठरवणे आणि त्याचे सत्र तयार करणे |
| `POST /challenge/verify` | समुदाय                | सत्राचा निकाल आणि IP बुद्धिमत्ता वाचणे            |
| `POST /precheck`         | पूर्व-तपासणी iframe   | अपलोडपूर्वी मसुद्याचा स्कोअर ठरवणे                |
| `GET /iframe/:sessionId` | लेखकाचा ब्राउझर       | पडताळणी पृष्ठ                                     |
| `POST /upload/authorize` | लेखकाचा क्लायंट       | Forge Images साठी संलग्न फाइल अधिकृत करणे         |

विनंती स्वाक्षरी आणि प्रतिसाद स्कीमांसह संपूर्ण करार [spam-blocker README](https://github.com/bitsocialnet/spam-blocker#api-contract) मध्ये आहे.
