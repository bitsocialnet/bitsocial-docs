# SpamBlocker

يقيّم SpamBlocker خطر البريد العشوائي في المنشورات والردود والأصوات قبل أن يقبلها المجتمع. يثبّت المجتمع حزمة التحدي، التي ترسل كل منشور إلى خدمة SpamBlocker. وتشغّل Bitsocial إحدى هذه الخدمات على `spamblocker.bitsocial.net`.

- **`@bitsocial/spam-blocker-challenge`** هي حزمة التحدي مفتوحة المصدر التي تثبّتها المجتمعات. وعقد التكامل الخاص بها ومخططاتها المشتركة وواجهة API الخاصة بها كلها علنية.
- **الخدمة المستضافة** تقيّم المنشورات وتقدّم صفحات CAPTCHA وتسجيل الدخول. أما أوزانها وقواعدها الاستدلالية التفصيلية فهي خاصة، كما توضح [سياسة الشيفرة المصدرية](https://github.com/bitsocialnet/spamblocker/blob/master/docs/architecture/hosted-service-source-policy.md).

**الشيفرة المصدرية:** [github.com/bitsocialnet/spamblocker](https://github.com/bitsocialnet/spamblocker)

## كيف يُفحص المنشور

1. يرسل تحدي المجتمع المنشور الموقّع إلى الخدمة، التي تُرجع درجة مخاطرة بين 0 و1.
2. إذا كانت الدرجة أقل من عتبة القبول التلقائي للمجتمع، يُقبل المنشور. وإذا بلغت عتبة الرفض التلقائي أو تجاوزتها، يُرفض المنشور ويرى المؤلف السبب.
3. بين العتبتين، يُعاد استخدام تسجيل الدخول المحفوظ للمؤلف إذا كان كافيًا. وإلا تظهر للمؤلف صفحة تحقق: اختبار CAPTCHA إذا كان CAPTCHA وحده قد يكفي للنجاح، أو تسجيل دخول. وعبر اتصال VPN أو وكيل أو مركز بيانات يقيّده المجتمع، يحتاج المؤلف إلى تسجيل دخول عند أي درجة أقل من عتبة الرفض التلقائي، ما لم ينطبق إعفاء من الإعفاءات المذكورة في سياسات الاتصال.
4. بعد ذلك يتحقق المجتمع من النتيجة لدى الخدمة ويطبّق قواعده الخاصة بالدولة ومخاطر IP ونوع الاتصال.

قبل رفع ملف مرفق، يمكن للعميل إجراء الفحص نفسه كفحص مسبق، مما يُغني معظم المؤلفين الذين كانوا سيُرفضون عن الرفع. ويُفحص المنشور مرة أخرى عند نشره، لذا قد يُرفض حتى بعد نجاح الفحص المسبق.

## درجة المخاطرة

| الإشارة           | الوصف                                                                                                           |
| ----------------- | --------------------------------------------------------------------------------------------------------------- |
| عمر الحساب        | تتلقى الحسابات الأحدث درجات مخاطر أعلى.                                                                         |
| الكارما           | الكارما المجتمعية المتراكمة تقلل من المخاطر.                                                                    |
| سمعة المؤلف       | بيانات من مفهرس يعمل في الخلفية ويتتبّع المؤلفين الذين يُقبلون أو تُزال منشوراتهم أو يُحظرون عبر المجتمعات.     |
| المحتوى والروابط  | تحليل النصوص والروابط، بما في ذلك المحتوى المتكرر.                                                              |
| السرعة            | المشاركات المتعاقبة السريعة من نفس المؤلف تزيد من المخاطر.                                                      |
| معلومات IP        | نوع الاتصال (Tor أو VPN أو وكيل أو مركز بيانات) ومخاطر IP. لا تتم مشاركة عناوين IP الأولية مع المجتمعات مطلقًا. |
| الحسابات المرتبطة | تؤدي كثرة الحسابات التي تنشر من شبكة واحدة إلى رفع المخاطر تدريجيًا.                                            |
| التحقق الاجتماعي  | تسجيلات الدخول السابقة على حساب المؤلف تخفّض المخاطر.                                                           |

## التحقق

تضرب كل خطوة مكتملة درجة المخاطرة في معامل، ويُقبل المنشور عندما تصبح النتيجة أقل من 0.4.

| الخطوة                                            | المعامل      |
| ------------------------------------------------- | ------------ |
| CAPTCHA (Cloudflare Turnstile)                    | × 0.7        |
| تسجيل الدخول باستخدام Google أو Apple أو Telegram | × 0.6        |
| تسجيل الدخول باستخدام مزوّد ثانٍ مختلف            | × 0.5 إضافية |

إذا لم يكن CAPTCHA كافيًا، يتبعه تسجيل دخول. وإذا لم يكن تسجيل الدخول كافيًا، يتبعه CAPTCHA إذا كان ذلك يُكمل الفحص، وإلا فتسجيل دخول عبر مزوّد ثانٍ.

### تسجيلات الدخول المحفوظة

تتذكر الخدمة الحساب الذي سجّل المؤلف الدخول به آخر مرة. ويُعيد أي منشور لاحق يحتاج إلى تحقق استخدامه كما لو أن المؤلف سجّل الدخول من جديد، إذا كان أحد منشورات المؤلف قد استخدمه خلال آخر 30 يومًا. وتُحتسب كل إعادة استخدام منشورًا من هذا القبيل، فتبدأ مدة الـ30 يومًا من جديد مع كل واحدة منها. وعندما يكون ذلك كافيًا، يُقبل المنشور دون CAPTCHA. وينتهي ذلك إذا فرض المجتمع حظرًا مرتبطًا بالحساب، وكذلك إذا أُزيل مزوّد الحساب من الخدمة.

## سياسات الاتصال

يمكن للمجتمعات تقييد المنشورات القادمة من اتصالات Tor وVPN (بما في ذلك iCloud Private Relay) والوكلاء ومراكز البيانات. وفي الخدمة المستضافة:

- **اتصالات VPN والوكلاء ومراكز البيانات** يمكنها النشر بعد تسجيل الدخول. وتوضح الصفحة سبب الحاجة إلى تسجيل الدخول وكيفية النشر من دونه بإيقاف VPN. وبعد ذلك يسري أي حظر في المجتمع أيضًا على الحساب المستخدم لتسجيل الدخول.
- **الحسابات الراسخة** مُعفاة من قيود VPN والوكلاء ومراكز البيانات، ولكن ليس من قيد Tor. ويصبح الحساب راسخًا بعد أن يجتاز CAPTCHA أو تسجيل دخول في 3 أيام مختلفة من اتصالات غير مقيّدة؛ ولا تُحتسب المنشورات التي قُبلت دون أيٍّ منهما. ولا تُحتسب الشبكة إلا لحساب واحد: فبمجرد أن يجتاز حساب آخر فحصًا منها، لا تُحتسب لأيٍّ من الحسابين. وفي المجتمع الذي حظر حسابًا على إحدى تلك الشبكات، لا يُحتسب شيء من هذا السجل.
- **Tor** يبقى مقيّدًا، إلا للمؤلفين الذين لديهم إعفاء أعدّه المجتمع: دور مشرف، أو القائمة البيضاء للمجتمع، أو اسم `.bso` موثَّق.

تخضع الملفات المرفقة التي تُرفع إلى Forge Images للقواعد نفسها. فعبر اتصال VPN أو وكيل أو مركز بيانات، يحتاج الرفع إلى فحص مسبق نجح بتسجيل دخول، أو إلى حساب راسخ. وعبر Tor، يحتاج إلى إعفاء موثَّق.

## الخصوصية

- **المشغّل** يخزّن عناوين IP الأولية ومحتوى المنشورات لاكتشاف إساءة الاستخدام، ويرسل عناوين IP إلى مزوّد خارجي لتصنيفها (proxycheck.io افتراضيًا).
- **المجتمعات** لا تتلقى سوى رمز الدولة ومخاطر IP وتقدير نوع الاتصال ونتيجة النجاح أو الفشل. ولا تتلقى أبدًا عنوان IP الأولي أو حساب تسجيل الدخول.
- **تسجيلات الدخول** لا تطلب أي بيانات للملف الشخصي. فلا تتلقى الخدمة من Google أو Apple أو Telegram سوى معرّف الحساب، ولا تتلقى أبدًا الاسم أو البريد الإلكتروني أو الصورة. وتحتفظ بالمعرّف مع المنشور دون حذف تلقائي، حتى يسري الحظر على الحساب أيضًا.
- **المؤلفون الذين يستخدمون VPN** تبقى عناوين IP الحقيقية الخاصة بهم مخفية عند تسجيل الدخول: فالخدمة لا ترى سوى عنوان VPN.

## الحد من المعدل

قبل التقييم، ترفض الخدمة المؤلفين الذين يتجاوزون حصتهم بالساعة أو باليوم من المنشورات والردود والأصوات. وتزداد الحصص مع عمر الحساب والسمعة الجيدة، وتتقلص بعد الحظر أو الإزالة.

## API

المسارات الرئيسية، نسبةً إلى `spamblocker.bitsocial.net/api/v1`:

| المسار                   | الجهة المستدعية             | الغرض                          |
| ------------------------ | --------------------------- | ------------------------------ |
| `POST /evaluate`         | إطار iframe للتحدي، المجتمع | تقييم منشور وإنشاء جلسته       |
| `POST /challenge/verify` | المجتمع                     | قراءة نتيجة الجلسة ومعلومات IP |
| `POST /precheck`         | إطار iframe للفحص المسبق    | تقييم مسودة قبل الرفع          |
| `GET /iframe/:sessionId` | متصفح المؤلف                | صفحة التحقق                    |
| `POST /upload/authorize` | عميل المؤلف                 | تفويض ملف مرفق لـ Forge Images |

يوجد العقد الكامل، بما في ذلك توقيع الطلبات ومخططات الاستجابة، في [ملف README الخاص بـ spamblocker](https://github.com/bitsocialnet/spamblocker#api-contract).
